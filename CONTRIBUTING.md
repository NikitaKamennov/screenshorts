# Участие в ScreenShorts Pro

Начни с [README](README.md), [статуса](docs/project-status.md) и
[справочника скриптов](scripts/README.md). Для правок интерфейса полезна
[пользовательская инструкция](docs/user-guide.md), для ядра —
[формат данных](docs/data-format.md).

## Сообщить об ошибке

В GitHub Issues укажи:

- ОС и версию; для Linux — оболочку и X11/Wayland, для проблем захвата — мониторы и DPI.
- Версию/коммит приложения, способ запуска: исходники, dev-EXE, полная папка,
  ZIP, установщик или .run. Для комплекта полезен SHA файла.
- Короткие шаги, ожидаемый результат и то, что произошло.
- Текст ошибки без личных путей и содержимого снимков; для OCR — состояние на карточке.

Прикладывай искусственные изображения, на которых воспроизводится проблема.
Не прикладывай личные скриншоты, .png.json, settings.json, библиотеки или
неотредактированные логи: JSON может содержать распознанный текст и заметки.
Облачный сервис для воспроизведения не нужен.

## Подготовить изменение

1. Сделай небольшое изменение с понятной целью. Выбери инструкцию сборки
   для своей платформы и отдельную библиотеку с искусственными данными.
2. Сохраняй общий Go-контракт и отдельные адаптеры Windows/Linux.
   Один платформенный runtime не переносится в окружение другого.
3. При изменении кнопок, настроек или сценариев обнови встроенную справку,
   README и затронутые docs. Будущие функции отделяй от работающего кода.
4. Для обычных изменений достаточно git add . из корня проекта.
   .gitignore разрешает исходные каталоги и публичные документы, исключая
   локальные данные/сборки. Перед коммитом просмотри git diff --cached.
   Для нового корневого файла или документа добавь разрешение в .gitignore;
   не обходи исключения данных и runtime через git add -f.
5. В описании PR объясни проблему и новое поведение, перечисли фактическую
   проверку и непроверенные платформы. Отдельно укажи миграции данных
   и новые зависимости.

В PR укажи, какие проверки выполнены фактически. Ручные сценарии для Windows — [здесь](docs/windows-acceptance.md),
для автономного Linux — [здесь](docs/linux-portable.md#ручная-приёмка).
Используй отдельный --data-root с вымышленными данными.

## Контракты, которые нужно сохранить

PNG + JSON остаются переносимой записью; пользовательский комментарий,
исходный и исправленный OCR различаются. Обработка получает окончательные
пиксели после обрезки/скрытия; старый OCR не присоединяется к другой версии
картинки. Ошибка обработки не блокирует сохранение PNG.

Локальность, одна тяжёлая задача, лимиты, отмена и ОС-изоляция —
часть устройства продукта. Не добавляй облачный fallback, запуск без sandbox
или автоматическое повышение лимитов после ошибки.

Собственный код — MIT; условия новых моделей/runtime проверяются отдельно,
с источником, версией, SHA и уведомлениями. Не применяй MIT приложения
к чужим весам или библиотекам.
