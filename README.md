# ScreenShooter Pro

Название и оформление обновлены 21 ноября 2026 года. Основной раздел —
**«Библиотека»**; прежние снимки и настройки продолжают читаться.
[Переименование и совместимость](docs/branding.md).

**Делай скриншоты как тебе удобно. Находи их по тексту.**

Локальный инструмент для захвата экрана, редактирования и хранения снимков
на Windows и Linux. Настраиваемые комбинации, четыре режима захвата, стрелки,
распознавание текста и библиотека с поиском — в одном приложении.

После сохранения снимок автоматически попадает в очередь OCR. Позже можно
найти его по словам с картинки или собственному комментарию: например,
«настройки уведомлений» или название сайта, если эти слова есть в тексте.
Скриншоты и текст обрабатываются на твоём ПК, без облачных AI API и подписки.

> Проект развивается. Самостоятельные комплекты уже собираются, но полная
> проверка выпуска на чистых ОС ещё не завершена. Точные результаты и открытые
> ограничения — в [статусе проекта](docs/project-status.md).

## Возможности

- **Четыре режима:** область с редактором, весь экран с редактором, тихий
  полный снимок и тихий снимок заранее заданной области. У каждого своя
  комбинация. Тихие режимы работают через адаптеры Windows/X11; в Wayland отключены.
- **Редактор перед сохранением:** карандаш, линии и стрелки, фигуры, обрезка,
  непрозрачное скрытие участков, undo/redo. После обычного захвата Enter
  сохраняет снимок и сворачивает приложение; в текстовых полях вводит новую строку.
- **Удобная раскладка:** панель с любой стороны снимка, перестановка блоков,
  разворачивание блока двойным щелчком, изменение размеров. Светлая/тёмная тема
  и настраиваемый основной цвет.
- **OCR русского и английского:** автоматическая обработка новых сохранений,
  ручное повторное распознавание, исправление текста, буфер и экспорт TXT.
  Ошибка OCR не мешает сохранить PNG.
- **Библиотека:** миниатюры и таблица, сортировки, группы по дням и общим словам,
  предпросмотр, выбор нескольких снимков, копирование файлов/текста,
  ZIP с метаданными, корзина и восстановление.
- **Локальное удаление фона:** U²-NetP / ONNX Runtime CPU, прозрачный PNG.
  Реализация включена в полные комплекты; функциональная приёмка инструмента
  ещё впереди.

Поиск сейчас текстовый: OCR, его исправленная версия и комментарии.
Семантическая модель и автоматическое описание объектов на картинке
не подключены. Снимок без текста можно снабдить комментарием или сохранить без него.

Скачай исходники через **Code → Download ZIP** либо клонируй этот репозиторий.
Дальнейшие команды выполняй из его корня — каталога с этим README и `go.mod`.
Для сборки достаточно исходников этого репозитория и указанных зависимостей.

### Windows: автономная папка

На машине сборки нужны Windows x64, 64-разрядный Windows PowerShell и Go 1.25+.
Первый проход загружает закреплённые компоненты и Go-модули.

~~~powershell
.\build-windows.cmd
~~~

Готовое приложение:
`.local-data\build\windows-bundle\ScreenShooterPro\ScreenShooterPro.exe`.

Переноси **всю папку ScreenShooterPro**. В ней находятся WebView2, Tesseract rus/eng,
Python, CPU-зависимости и модель удаления фона. На пользовательском ПК
их отдельно устанавливать не нужно.

Для ZIP используй `.\build-portable.cmd`, для папки + ZIP + установщика —
`.\build-release.cmd`. Параметры, точные пути и обновление описаны
в [инструкции Windows](docs/windows-quick-build.md).

### Linux: запуск из исходников

После установки Go 1.25+, C toolchain, GTK3 и WebKitGTK 4.1:

~~~bash
bash scripts/start-dev.sh
~~~

`go run` сам компилирует временную программу. Функции те же, что у обычной
Linux-сборки при одинаковом runtime-профиле; после правок нужен перезапуск.
Tesseract и компоненты фона для лаборатории готовятся отдельно.
[Зависимости и полный порядок](docs/build-linux.md).

### Linux: автономный комплект

На подготовленной Ubuntu 24.04 / Mint 22 x86_64:

~~~bash
bash scripts/build-linux-portable.sh
~~~

В `.local-data/linux-x64/dist/` появятся готовая папка, `.run`, `.tar.gz`,
спецификация и SHA-256. Пользователю не нужны установленные Go, Python,
Tesseract и GTK/WebKitGTK. Формат .run распаковывается в пользовательский кэш
и не требует FUSE. [Подготовка машины и пересборка](docs/linux-portable.md).

## Платформы и ограничения

| Платформа | Текущая реализация |
| --- | --- |
| Windows x64 | Win32-захват/горячие клавиши/трей, WebView2. Захват, OCR rus/eng, поиск и библиотека проверялись на Windows 10; полная матрица ещё открыта |
| Ubuntu 24.04 / Mint 22.x x86_64 | Базовый профиль автономного комплекта, glibc 2.39+. Сборка выполнена; функциональная проверка этого комплекта на чистых ОС впереди |
| Linux X11 | Собственный захват и комбинации, включая тихие режимы; часть базовых сценариев проверена вручную |
| Linux Wayland | Захват и комбинации через доступные порталы окружения; тихие режимы отключены. Совместимость зависит от оболочки |
| macOS, ARM, 32 bit | Сборки не подготовлены |

Linux-комплект включает пользовательские библиотеки, но требует графической
сессии, D-Bus, systemd user manager, cgroup v2 и разрешённой ОС-изоляции.
Трей зависит от оболочки. Это не универсальный бинарник для любого Linux:
[спецификация файла](docs/linux-download-spec.txt).

Для текущего хранения нужны локальные файловые системы с жёсткими ссылками:
NTFS в Windows, ext4 и совместимые в Linux. FAT/exFAT и сетевые папки
не входят в проверенный профиль.

## Технологии и устройство

| Часть | Технология и роль |
| --- | --- |
| Ядро | Go 1.25+: настройки, PNG/JSON, поиск, библиотека, очередь задач и ограничения |
| Desktop | Wails v2.15.0; WebView2 в Windows, GTK3/WebKitGTK 4.1 в Linux |
| Интерфейс | Встроенные HTML/CSS/JavaScript без npm-сборки и внешних ресурсов |
| Захват и ОС | Win32, X11/XGB, D-Bus и XDG portals; отдельные адаптеры платформ |
| OCR | Локальный Tesseract rus+eng на CPU |
| Удаление фона | Собственный Python-worker, U²-NetP, ONNX Runtime CPU; закреплённые wheels и SHA модели |
| Хранение | PNG + соседний `.png.json`; SQLite/FTS и векторный индекс пока в плане |
| Комплектование | PowerShell / Inno Setup для Windows; Bash / Python и статический Go-launcher для Linux |

Node.js и Wails CLI для сборки приложения не требуются. Видеокарта/CUDA
для текущих OCR и удаления фона не нужны. Скорость и потребление памяти
на разных устройствах пока не измерены.

~~~text
cmd/skrinpolka/          desktop-приложение и мост к интерфейсу
cmd/linux-portable/     самораспаковка Linux .run
cmd/linux-worker-guard/ запуск Linux-worker с проверкой cgroup
frontend/web/           встроенный интерфейс
internal/core/          данные, настройки, поиск и библиотека
internal/platform/     платформенные функции Windows / Linux
internal/analysis/     локальные задачи OCR и удаления фона
internal/sandbox*/     отдельная защита процессов Windows / Linux
workers/background/    worker, hash-lock и manifest модели
config/                runtime-профили и параметры комплектов
scripts/               запуск, сборка и комплектование
schemas/               формат переносимых метаданных
licenses/              уведомления стороннего кода и компонентов
docs/                  инструкции, статус и планы
~~~

Одновременно выполняется одна тяжёлая задача. OCR и удаление фона имеют
лимиты RAM/CPU/времени, отмену, проверки свободных ресурсов и изоляцию:
AppContainer/Job Object в Windows, cgroup v2/bubblewrap в Linux.
Отказ защиты приводит к ошибке обработки; PNG можно сохранить без результата.
[Подробности локальных workers](docs/local-workers.md).

## Данные и приватность

Новые имена снимков: `ScreenShooter Pro ГГГГ-ММ-ДД ЧЧ-ММ-СС.png`.
Рядом хранится `.png.json` с OCR, его ручной правкой, комментарием,
размерами и происхождением результата. Для переноса всей записи копируй пару
или используй ZIP из библиотеки: один PNG не переносит текст поиска.

| Режим | Каталог настроек и данных по умолчанию |
| --- | --- |
| Windows, включая portable | `%LOCALAPPDATA%\Skrinpolka` |
| Linux, обычный/автономный запуск | `$XDG_DATA_HOME/skrinpolka` или `~/.local/share/skrinpolka` |
| Linux, `scripts/start-dev.sh` / `start-local.sh` | `.local-data/linux-dev` внутри исходников |

Папка снимков меняется в настройках; прежние файлы при этом не перемещаются.
Для отдельной библиотеки есть `--data-root`, для runtime — `--runtime-config`.
Старые имена `skrinpolka`, схема `skrinpolka-screenshot-v1` и Go-модуль
сохранены ради совместимости.

Сеть используется при явной подготовке зависимостей на машине сборки.
Готовый полный комплект содержит движки и модели для локальной обработки.
В репозитории находятся исходники, конфиги, lock-файлы и уведомления;
личные снимки, библиотеки, runtime, веса и готовые сборки исключены из Git.
