# Настройки и локальный OCR

**Linux portable:** `linux-release.json` задаёт целевую платформу и состав
снимка runtime. Сборщик создаёт отдельный профиль в папке комплекта.
Поля `ocr.linux_runtime_root` и `background_removal.linux_runtime_root`
указывают на комплектный runtime с собственным `usr/`: worker запускается
в bubblewrap с этим read-only /usr. Прежние профили без поля сохраняют
системный Linux-адаптер; Windows его не использует. [Подробности](../docs/linux-portable.md).

Исходники конфигурации подготовлены без запуска приложения и workers.

## Настройки приложения

`settings.json` создаётся внутри каталога данных. Его расположение описано в
[README](../README.md). Поля обслуживаются Go-ядром и интерфейсом:

- `library_directory` — абсолютная папка для новых PNG/JSON и текущей галереи.
  Изменение папки не переносит прежние файлы.
- `capture_shortcut` — глобальная комбинация; пустое значение отключает её.
  На первом старте интерфейс предлагает `Ctrl+Shift+PrintScreen`.
- `screen_shortcut` — отдельная комбинация для всего экрана, изначально пустая.
- `silent_shortcut` — тихий полный снимок без редактора/активации, изначально
  пустая. Windows/X11; на Wayland не регистрируется. Все четыре комбинации должны
  различаться; старые настройки читаются без миграции библиотеки.
- `silent_area_shortcut` — отдельная комбинация тихого снимка заданной области,
  изначально пустая. Перед назначением нужно выбрать область в настройках.
- `silent_region` — координаты `x`, `y`, `width`, `height` и границы рабочего
  стола `desktop_x`, `desktop_y`, `desktop_width`, `desktop_height` в физических
  пикселях. Записывается сразу отдельной кнопкой выбора; общая форма сохраняет
  последнюю область. При изменении границ рабочего стола захват отклоняется.
- `silent_region.desktop_topology` — необязательный SHA-256 конфигурации
  логических дисплеев Windows: имена, физические границы, системный масштаб,
  основной дисплей. Windows-тихий захват требует его совпадения; старая
  область без поля просит повторный выбор. Linux его не требует. Поле
  подготовлено в W2 без запусков, не входит в sidecar снимка.
- `editor_panel_position` — `right`, `bottom`, `left`, `top`; по умолчанию `right`.
- `editor_tool_order` — порядок блоков `comment`, `drawing`, `ocr`, `photo`.
  Положение и порядок сохраняются кнопкой панели и перетаскиванием заголовков,
  отдельно от сохранения общих настроек. Эти поля не входят в sidecar снимка.
- `editor_panel_width`, `editor_panel_height` — размеры панели слева/справа
  и сверху/снизу в CSS-пикселях; по умолчанию 320 и 280, допустимо 240–1600
  и 140–1200. Интерфейс дополнительно ограничивает их доступным окном.
- `editor_width`, `editor_height` — размер редактора, по умолчанию 1200×900;
  пределы 680–3840 и 480–2160, с ограничением текущим окном. Сохраняются вместе
  с раскладкой отдельной операцией; общая форма их не перезаписывает.
- `theme` — `light` или `dark`, по умолчанию `light`.
- `accent_color` — основной цвет `#RRGGBB`, по умолчанию `#2d6a4e`.
  Переключатель шапки сохраняет только оформление. В форме настроек цвет/тема
  сначала показываются в предпросмотре и записываются по «Сохранить».
- `start_in_tray` — скрывать окно при последующем запуске только с доступным
  треем; первый запуск остаётся видимым. По умолчанию `false`.
- `setup_complete` — пользователь сохранил начальную настройку приложения.
- `auto_index` — историческое имя флажка «Распознавать ещё в редакторе».
  По умолчанию `false`: ранний OCR не запускается, но после сохранения **каждый
  новый снимок** обрабатывается ядром независимо от этого флажка. Готовый OCR
  используется повторно, текущий продолжается. Явная отмена сохраняется.
  Недоступный движок записывается как `unavailable`. SQLite и векторов пока нет.

## Профиль OCR

`runtime-linux.json` и `runtime-windows.json` имеют схему
`skrinpolka-runtime-v1`. Передать другой профиль можно через
`--runtime-config /абсолютный/путь/runtime.json`. Без параметра профиль ищется
в `config/runtime-<os>.json` рядом с бинарником. `start-local.sh` передаёт
Linux-профиль из исходников явно.

`background_removal` в исходных профилях выключен. Явная команда
`scripts/setup-background.py` создаёт отдельный профиль в
`.local-data/background-<os>/runtime-<os>.json`, сохраняя OCR базового профиля.
В нём задаются `enabled`, Python `executable`, `script`, `model_path`, обязательный
`model_sha256`, `model_id=u2netp`, read-only `read_roots`, `memory_bytes`, `threads`,
`timeout_seconds`. Исходный профиль не перезаписывается. `start-dev.sh`,
`start-local.sh` и `start-windows.ps1` выбирают подготовленный профиль, если есть;
при своей команде передавай его через `--runtime-config`.
Подробнее: [локальное удаление фона](../docs/background-removal.md).

Относительные пути разрешаются от папки самого JSON. Блок `ocr` содержит:

| Поле | Значение |
| --- | --- |
| `enabled` | Разрешить OCR; наличие профиля не устанавливает движок |
| `executable` | Локальный Tesseract CLI |
| `tessdata_directory` | Папка с `rus.traineddata`, `eng.traineddata` |
| `languages` | `rus`, `eng` или оба языка |
| `read_roots` | Каталоги runtime/языков, выдаваемые worker только для чтения |
| `memory_bytes` | Память процесса/дерева: начальный профиль 805306368 байт |
| `threads` | Начальный предел потоков 2; допустимо 1–4 |
| `timeout_seconds` | Начальный timeout 90; допустимо 1–300 |
| `model_id`, `model_revision` | Происхождение результата; не заменяют manifest |

Linux-профиль рассчитан на системные пакеты Ubuntu 24.04 / Mint 22.
Исходный Windows-профиль ожидает `tools/tesseract/` рядом с EXE. Режим без
параметров копирует только этот dev-конфиг. Полные `-Bundle`/`-Portable`/`-Release`
готовят собственный относительный профиль и включают OCR/языки/Python/модель
и полный WebView2. `system-package` и
`bundle-manifest` — обозначения источника, **не подтверждение SHA или наличия
готового комплекта**. В W3 подготовлен `windows-downloads.json` со всеми
закреплёнными raw-артефактами (URL/размер/SHA/происхождение/лицензии) и
отдельным Windows Python cp313. Исходные background lock/model не обновлялись.
Кэш получен, компоненты распакованы, EXE скомпилирован. Захват, OCR и библиотека
проходили ограниченную Windows-проверку; полной приёмки выпуска пока нет. [Команды и состояние](../docs/windows-quick-build.md).

`windows-release.json` задаёт отображаемую версию, числовую версию установщика,
имена ZIP/установщика и статус ручной приёмки. `-Release` кладёт оба результата
и SHA в `.local-data/releases/windows-x64/release/`. `not-accepted` означает,
что компиляция не заменяет ручной проверки приложения и установщика.

Смена путей/совместимых языковых файлов требует перезапуска приложения,
но не пересборки оболочки. Новый движок или протокол требует адаптации кода.
Release manifests закрепляют состав файлов и SHA; manifests компонентов — ревизии, источник, SHA-256,
лицензии и уведомления всех артефактов. Веса и runtime не входят в исходники.

Подробности защиты и текущих ограничений: [local-workers.md](../docs/local-workers.md).
