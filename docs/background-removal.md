# Локальное удаление фона

Подготовлена реализация U²-NetP через ONNX Runtime CPU, с отменой и undo/redo.
**Функциональная приёмка удаления фона не подтверждена; качество, память
и скорость не измерены.** Полные Windows/Linux-комплекты уже собираются
с этим runtime; их сборка не запускает модель. Пользователю полного комплекта
выполнять описанный ниже dev-setup не нужно. [Статус](project-status.md).
Размер U²-NetP — 4 574 861 байт; источник, размер и SHA-256 закреплены
в manifest. Dev-setup создаёт отдельное окружение и профиль в .local-data,
полные сборщики готовят собственные runtime. В Git веса не входят.

## Подключение Linux для разработки

Нужен системный CPython **3.12 или 3.13** под `/usr` (включая `/usr/local`),
Linux x86_64. Другие префиксы Python текущий setup отклоняет: для них нужен
отдельный адаптер путей изоляции. На Ubuntu 24.04
системный Python — 3.12; модуль venv при необходимости устанавливается отдельно:

```bash
sudo apt install python3-venv
python3 scripts/setup-background.py
bash scripts/start-dev.sh
```

`setup-background.py` — явная сетевая подготовка: создаёт **своё** окружение
`.local-data/background-linux/.venv`, устанавливает только закреплённые CPU-
wheels с обязательными SHA из lock, скачивает U²-NetP и сверяет размер/SHA.
Другие проекты/окружения не используются. Приложение, модель и тесты этот скрипт
не запускает. Перед подготовкой закрой старую копию приложения.

`start-dev.sh` компилирует временную программу через `go run`, выбирает новый
профиль автоматически и использует прежние `.local-data/linux-dev` данные.
Требуются обычные [зависимости Go/Wails](build-linux.md).
Для запуска готового бинарника сначала обнови его через `build-linux.sh`,
затем `start-local.sh` также выберет подготовленный профиль.

Если используешь свою команду `go run`, замени только профиль:

```bash
--runtime-config "$PWD/.local-data/background-linux/runtime-linux.json"
```

По умолчанию копируются настройки OCR из `config/runtime-linux.json`, пути
делаются абсолютными. Для своего OCR-профиля передай его явно:

```bash
python3 scripts/setup-background.py --base-config /абсолютный/путь/runtime-linux.json
```

Исходный профиль не меняется. Подготовка не отменяет требования systemd user,
cgroup v2 и bubblewrap; при отказе изоляции обработка не запускается.

## Подключение Windows для разработки

Работай **на Windows amd64**, с отдельно установленным CPython 3.12/3.13 и
WebView2. Сначала [собери приложение](windows-build.md), затем в PowerShell:

```powershell
py -3.12 .\scripts\setup-background.py --base-config .\.local-data\build\windows-x64\config\runtime-windows.json
& .\scripts\start-windows.ps1
```

Компоненты создаются в `.local-data\background-windows\`, без использования
Linux-venv. Новый профиль сохраняет OCR из указанного файла; Tesseract это
не устанавливает. Launcher выбирает профиль фона, а данные приложения остаются
в прежнем `%LOCALAPPDATA%\Skrinpolka\`. Для прямого EXE укажи его явно:

```powershell
& .\.local-data\build\windows-x64\ScreenShortsPro.exe --runtime-config "$PWD\.local-data\background-windows\runtime-windows.json"
```

Обработка использует прежние Windows AppContainer/Job Object. Проверка на
реальной Windows ещё требуется, включая доступ Python/DLL/модели через ACL.
Подготовленное окружение — рабочее окружение разработчика, не portable-комплект.

## Как работает инструмент

«Удалить фон» берёт сведённый PNG текущего редактора, включая обрезку и скрытие,
ждёт общий слот с OCR и запускает отдельный Python-процесс без сети. Внутри
worker ONNX Runtime получает только CPU provider, 2 intra-op потока, один inter-op
и выключенное spinning. Профиль ограничивает процесс 1 GiB и 120 секундами;
это предел, а не измеренное потребление/длительность. Сохраняются проверка RAM
с резервом, свободного диска, отмена и ОС-изоляция. Защита не обходится.

Модель получает RGB 320×320 по опубликованному контракту U²-NetP; маска
масштабируется до исходного размера и умножается на существующую альфу.
Полностью прозрачные RGB очищаются. SHA проверяется хостом и worker,
выходной PNG повторно проверяется хостом (размеры/20 MiB/16 млн пикселей).

Результат становится отдельной отменяемой операцией редактора. До успешного
применения пиксели не меняются. При отмене, ошибке, закрытом или изменившемся
черновике результат не применяется. История держит максимум четыре результата
фона и 64 млн пикселей таких снимков; чтобы повторить при заполнении, отмени
предыдущую операцию либо сохрани и начни новый черновик.

После изменения пикселей старый OCR инвалидируется. Ранний OCR запускается
по настройке, после сохранения действует общий обязательный OCR. Приватные
`work/background-*` удаляются после завершения процесса, в библиотеку не попадают.
После аварии возможны остатки; автоматический поиск/очистка всех остатков не обещается.

Модель предназначена для выделения заметного объекта, а не для точного
распознавания элементов интерфейса. Волосы/стекло/сложные края требуют оценки.
Кисть ручной коррекции маски, замена фона и генеративная дорисовка пока не реализованы.

## Ручная приёмка

Подтверждённой функциональной приёмки этого инструмента пока нет.
Следующие сценарии выполняются отдельно от подготовки компонентов и сборки.

1. После выхода из старого процесса запусти `bash scripts/start-dev.sh`.
   Открой «?» в шапке и F1: видна инструкция, закрытие возвращает к снимку.
2. На безопасном снимке фото нажми «Удалить фон». После завершения должна
   появиться клетчатая прозрачность, картинка сохраняет прежние размеры.
3. Ctrl+Z возвращает фон, Ctrl+Shift+Z снова убирает его без очереди/запуска модели.
   Обрезка, стрелки и комментарий продолжают работать.
4. Останови задачу сразу после нажатия, во время подготовки, ожидания и работы,
   затем закрой черновик во время обработки. Ранняя отмена должна предотвращать
   запуск worker; поздняя отмена старого запроса не должна остановить новый.
   Картинка не меняется, поздний результат не попадает в следующий снимок.
5. Сохрани PNG и открой его в просмотрщике с прозрачностью. Старый текст с
   удалённого фона не должен переноситься в OCR; после нового OCR ищется
   только текст итоговых пикселей/комментария. Проверь и undo перед сохранением.
6. При недоступных компонентах/отказе изоляции программа должна показать причину,
   сохранить прежний черновик и позволить обычное сохранение. Не снимать защиту
   и не повышать лимиты для обхода ошибки. Windows проходит свой отдельный сценарий.
