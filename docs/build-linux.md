# Linux: запуск из исходников и обычная сборка

Здесь описана **лаборатория разработчика с системными зависимостями**.
Для переносимой папки, .run и .tar.gz используй
[автономный комплект](linux-portable.md). Windows-компоненты не требуются.

## Подготовка

Начальный профиль: Ubuntu 24.04 / Linux Mint 22.x, x86_64,
обычная графическая сессия. Нужен **Go 1.25+** в PATH.
Системный пакет Go может быть другой версии; ориентируйся на go.mod.

Зависимости компиляции Go/Wails с WebKitGTK 4.1:

~~~bash
sudo apt update
sudo apt install build-essential pkg-config libgtk-3-dev libwebkit2gtk-4.1-dev
~~~

Скрипты сами задают CGO_ENABLED=1 и тег webkit2_41.
npm/Node.js и Wails CLI не нужны. Первый проход может загружать
закреплённые Go-модули; текст снимков для этого не используется.
Приложение не запускай через sudo.

Все следующие команды выполняются из корня репозитория.

## Вариант 1: работать из исходников

~~~bash
bash scripts/start-dev.sh
~~~

Это go run того же desktop-приложения: Go сам собирает временную программу
и запускает её. Отдельно вызывать build-linux.sh после каждой правки не нужно.
При одинаковом runtime-профиле функциональность совпадает с обычным бинарником.

**Автоматической перезагрузки нет.** После изменения Go, HTML, CSS или JS
полностью выйди из приложения через меню трея и повтори команду.
Если лишь закрыть окно, работающая копия может остаться в трее:
повторный запуск вернёт старое окно.

## Вариант 2: собрать постоянный бинарник

~~~bash
bash scripts/build-linux.sh
bash scripts/start-local.sh
~~~

Первая команда компилирует .local-data/build/linux-x64/ScreenShortsPro
и копирует соседний config/runtime-linux.json. Она не запускает приложение.
Вторая запускает этот бинарник; изменения исходников автоматически в него
не попадают. После изменений повтори сборку.

Это небольшой результат для разработки. Он использует системные GTK/WebKit
и выбранные runtime; копирование одного бинарника не даёт автономный комплект.

## Лабораторные данные и runtime

Оба launcher-скрипта используют отдельный --data-root:
.local-data/linux-dev внутри репозитория. В нём создаются settings.json
и начальная library/. Пользовательский каталог обычной установки не затрагивается.

Профиль выбирается в таком порядке:

1. .local-data/background-linux/runtime-linux.json, если подготовлен.
2. config/runtime-linux.json из исходников.

Свой профиль или отдельный каталог данных можно передать дополнительными
аргументами приложения:

~~~bash
bash scripts/start-dev.sh --data-root "$HOME/ScreenShorts Lab" --runtime-config "$HOME/ScreenShorts Lab/runtime-linux.json"
~~~

Оба пути в примере абсолютные; сам JSON нужно подготовить заранее.
Для start-local.sh действуют те же аргументы. Поля и разрешение путей —
в [справочнике конфигурации](../config/README.md).

## Системный OCR rus/eng

Для распознавания в лаборатории:

~~~bash
sudo apt install tesseract-ocr tesseract-ocr-rus tesseract-ocr-eng bubblewrap
~~~

Базовый профиль ожидает /usr/bin/tesseract и
/usr/share/tesseract-ocr/5/tessdata/. Если в твоём дистрибутиве пути другие,
поправь executable, tessdata_directory и read_roots в своём runtime JSON
и перезапусти приложение. Пересобирать оболочку из-за смены путей не нужно.

Каждый новый сохранённый снимок ставится в очередь OCR, даже если раннее
распознавание в редакторе выключено. Флаг auto_index управляет именно
**ранним OCR**, а не индексацией сохранений. Уже существующие снимки
без результата автоматически все подряд не распознаются: запускай OCR
из карточки. Ручная отмена также требует явного повторного запуска.

При недоступном OCR сохраняются PNG и комментарий; ошибка не блокирует снимок.

Для файлового буфера полки лаборатория использует `xclip` в X11 или `wl-copy`
в Wayland; для открытия папки — `xdg-open`. При отсутствии утилит установи:

~~~bash
sudo apt install xclip wl-clipboard xdg-utils
~~~

## Отдельный Python-worker удаления фона

Нужен системный CPython 3.12/3.13 под /usr, включая /usr/local, и модуль venv.
Для базовой Ubuntu 24.04:

~~~bash
sudo apt install python3.12-venv
python3 scripts/setup-background.py
bash scripts/start-dev.sh
~~~

Setup явно загружает hash-locked CPU wheels и модель U²-NetP, сверяет SHA,
создаёт собственное окружение .local-data/background-linux/.venv и профиль.
Не меняет системный Python и не использует Windows/чужие venv.
Он не запускает инференс; функциональная проверка инструмента ещё впереди.
[Подробности удаления фона](background-removal.md).

Автономный Linux-сборщик готовит собственный runtime независимо от этой
лаборатории; запускать dev-setup перед ним не нужно.

## Требования ОС и ресурсы

Для обработки нужны systemd user manager, cgroup v2 с memory/CPU/pids
и разрешённый bubblewrap/user namespaces. При запрете ОС-изоляции worker
завершится ошибкой; незащищённого повторного запуска нет.
Контейнер и headless-сессия не являются начальным профилем.

Начальный бюджет OCR — 768 MiB, два потока, 90 секунд; удаления фона —
1 GiB, два потока, 120 секунд. Плюс проверяется свободный резерв RAM и диск.
Это лимиты допуска, не измеренное потребление. Одновременно работает
одна тяжёлая задача. [Устройство защиты](local-workers.md).

В X11 реализованы собственные захват и глобальные комбинации. Wayland
использует Screenshot/GlobalShortcuts portals; поддержка зависит от backend
рабочего стола, тихие режимы отключены. Трей требует StatusNotifierItem
в оболочке. При недоступном трее приложение сохраняет обычное окно.

## Статус и типичные вопросы

Базовые захват, OCR и смена комбинации раньше проверялись вручную.
Это не приёмка актуальной версии на всех Linux:
[статус проверок](project-status.md).

- **Открылось старое окно:** выйди через трей из прежней копии, затем запускай новую.
- **После правок ничего не изменилось:** перезапусти start-dev.sh либо пересобери бинарник.
- **PNG есть, текста в поиске нет:** посмотри состояние OCR на карточке;
  для старого снимка нажми «Распознать заново».
- **Снимок без текста:** добавь необязательный комментарий, чтобы искать по нему.
- **Ошибка sandbox/cgroup:** смотри доступность изоляции и ресурсов;
  не отключай ограничения ради повторного запуска.
- **Нужно передать приложение другому человеку:** собирай [полный комплект](linux-portable.md),
  а не копируй лабораторный бинарник.
