# Публикация исходников и обычные коммиты

В Git входят исходники ScreenShorts Pro, публичные инструкции, конфиги,
lock-файлы, manifests и лицензии. Готовые установщики/архивы, runtime, модели,
скриншоты, метаданные пользователя и локальные материалы исключены.

## Как работает .gitignore

Корень репозитория и docs используют список разрешённых файлов/каталогов.
Новый случайный файл в корне или новая заметка в docs не попадут при
git add . в индекс. В разрешённых исходных каталогах дополнительно исключены
окружения, сборки, модели, изображения, базы, логи, ключи и временные файлы.

Поэтому при обычных изменениях кода достаточно:

~~~bash
git add .
git diff --cached --stat
git commit -m "Describe the change"
git push
~~~

Выполняй git add . из корня проекта, чтобы включить все его изменения,
включая удаления. Чтобы посмотреть точный состав и содержимое перед коммитом:

~~~bash
git diff --cached --name-only
git diff --cached
~~~

Для нового нужного файла в корне или публичного документа добавь разрешение
в .gitignore. Не используй git add -f для локальных данных и сборок.
Правила не определяют содержимое произвольного исходного файла:
не записывай секреты и личные данные в публикуемый код/конфиги.

.gitignore не снимает уже отслеживаемый файл с учёта. Если он больше не должен
публиковаться, сохрани локальную копию и убери только из индекса:

~~~bash
git rm --cached -- path/to/file
~~~

Если файл содержал чувствительные данные в прежних коммитах, обычное удаление
из нового коммита не очищает историю.

## Первый коммит

Если проект скачан ZIP-архивом и .git ещё нет:

~~~bash
git init -b main
~~~

Затем:

~~~bash
git add .
git diff --cached --stat
git commit -m "Initial ScreenShorts Pro sources"
~~~

Создай на GitHub пустой репозиторий без дополнительных README, .gitignore
или лицензии: эти файлы уже есть в исходниках.

Если SSH-доступ настроен, подставь свой аккаунт вместо YOUR_ACCOUNT:

~~~bash
git remote add origin git@github.com:YOUR_ACCOUNT/screenshorts.git
git remote -v
git push -u origin main
~~~

Для существующего origin его можно поменять через git remote set-url;
повторно добавлять origin не нужно.

## Исправить первый коммит до отправки

Когда первый коммит ещё не отправлялся, очисти файлы/индекс и замени его:

~~~bash
git add .
git diff --cached --stat
git commit --amend --no-edit
git push -u origin main
~~~

Так в отправляемой ветке останется один исправленный начальный коммит.
Не применяй этот порядок к уже опубликованной общей истории без согласования.

## Исходники и готовый выпуск

Состояние функций и проверок — в [статусе проекта](project-status.md).
Самостоятельные комплекты требуют отдельной проверки на чистых ОС.
Цикл Windows-установщика и удаление фона ещё не приняты полностью;
[аудит Windows-уведомлений](windows-notices.md) открыт.

MIT покрывает собственный код. У библиотек, движков и моделей отдельные
условия: сохраняй THIRD-PARTY, licenses, manifests и SHA. Готовые runtime
не добавляются в Git. Для Linux рядом с файлом скачивания нужна
[спецификация совместимости](linux-download-spec.txt).
