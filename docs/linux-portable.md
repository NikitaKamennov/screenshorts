# Linux: автономный комплект и пересборка

Сборщик готовит полную папку приложения, архив и самораспаковывающийся
исполняемый файл. Это отдельный путь от [лаборатории разработчика](build-linux.md).
На 18 ноября 2026 выполнены полная сборка и повторная сборка с `--offline`.
Приложение и workers из этого комплекта не запускались; статус приёмки —
**manual-pending**. [Общий статус проекта](project-status.md).

## Для кого файл

Цель первого выпуска — **Ubuntu 24.04 / Linux Mint 22.x, x86_64, glibc 2.39+**.
У других дистрибутивов/архитектур совместимость пока не подтверждена.
Полная [спецификация для страницы скачивания](linux-download-spec.txt)
также включается в дистрибутив и лежит рядом с файлами для размещения.

Go нужен только разработчику. В готовом комплекте находятся GTK/WebKitGTK,
Tesseract с rus/eng, свой Python 3.12/stdlib, CPU wheels ONNX/NumPy/Pillow,
U²-NetP, bubblewrap и утилиты файлового буфера. Веса и среды в Git не входят.
GUI использует базовую glibc ОС; worker получает комплектную glibc в private /usr.

ОС предоставляет desktop-сессию, D-Bus, systemd user manager, cgroup v2,
драйверы и разрешённые user namespaces. AppArmor/политики ядра могут запрещать
bubblewrap: при этом обработка выдаёт ошибку, никаких отключений защиты нет.
Свой Python сам по себе эти системные требования не устраняет.

В X11 реализованы четыре режима. Wayland использует системные порталы
для захвата/клавиш; тихие режимы сейчас отключены. Трей зависит от оболочки.

## Одна команда для пересборки

Из корня ScreenShorts Pro:

```bash
bash scripts/build-linux-portable.sh
```

Команда каждый раз собирает свежий Go/HTML/CSS/JS, статический launcher .run
и guard для обработки. Готовый runtime берёт из собственного проверяемого кэша.
Приложение, OCR, модель и тесты после сборки не открываются.
Перед запуском новой версии выйди из старой через меню трея: иначе
single-instance вернёт прежнее окно вместо нового приложения.

После первого полного прохода можно явно запретить сетевые загрузки:

```bash
bash scripts/build-linux-portable.sh --offline
```

Параметр требует готового runtime и нужных Go-модулей в кэше. Недостающие
компоненты дадут ошибку. После изменения модели/lock/сборщика runtime или
обновления системных пакетов на машине сборки нужен явный новый снимок:

```bash
bash scripts/build-linux-portable.sh --refresh-runtime
```

Пересборка runtime использует закреплённые wheels/модель из кэша; обновление
версий в исходных lock/manifest — отдельное изменение. Прежний runtime
сохраняется под `runtime-previous-…`, существующие папки выпуска не удаляются.
Не удаляй папку выпуска/кэш, пока из неё работает приложение.

## Машина сборки

Нативная Ubuntu 24.04 / Mint 22 x86_64, системный `/usr/bin/python3` 3.12,
Go 1.25+, C toolchain, GTK3/WebKitGTK 4.1 development-пакеты, Python venv,
binutils, dpkg/APT и glib-compile-schemas/gio-querymodules; от 6 GiB свободного
места на начало прохода. Список runtime-пакетов — `config/linux-release.json`.
Скрипт ничего не устанавливает в ОС: использует установленные пакеты и
собственное окружение сборочных инструментов в `.local-data/linux-x64/cache`.

Go 1.25+ установи отдельно и добавь в PATH. Для базовой Ubuntu/Mint
установи сборочные инструменты:

~~~bash
sudo apt update
sudo apt install build-essential pkg-config libgtk-3-dev libwebkit2gtk-4.1-dev \
  python3.12 python3.12-venv binutils libglib2.0-bin
~~~

Комплектователь читает файлы уже установленных runtime-пакетов. Подготовь
их на **машине сборки**; получателю приложения этот шаг не нужен:

~~~bash
sudo apt install libwebkit2gtk-4.1-0 libjavascriptcoregtk-4.1-0 \
  libgtk-3-0t64 libgtk-3-common libglib2.0-0t64 libglib2.0-data \
  libgdk-pixbuf-2.0-0 libgdk-pixbuf2.0-common librsvg2-common glib-networking \
  gsettings-desktop-schemas shared-mime-info adwaita-icon-theme \
  hicolor-icon-theme fonts-dejavu-core tesseract-ocr tesseract-ocr-rus \
  tesseract-ocr-eng bubblewrap xdg-dbus-proxy python3.12-minimal \
  libpython3.12-minimal libpython3.12-stdlib xclip libgl1-mesa-dri \
  libegl-mesa0 libglx-mesa0 libgbm1
~~~

Список соответствует текущему config/linux-release.json; при изменении
состава ориентируйся на него. Эти команды выполняются один раз по необходимости,
сам build-linux-portable.sh системные пакеты не устанавливает. Перед первым
проходом не нужно запускать лабораторный setup-background.py.

Первый проход скачивает Go-модули, hash-locked Python wheels и при необходимости модель.
wl-clipboard получает как закреплённый APT-архив с SHA из метаданных репозитория,
распаковывает в свой кэш, не устанавливая пакет в систему.
Сборочный кэш закрыт от параллельной сборки файловой блокировкой.
Системные файлы только читаются, личные скриншоты не используются.

## Результаты и запуск

Выходной каталог: `.local-data/linux-x64/dist/`.
В нём находятся:

| Результат | Назначение |
| --- | --- |
| `ScreenShortsPro-<source-id>-<suffix>/` | Полная готовая папка; внутри запускной файл ScreenShortsPro |
| ScreenShortsPro-Ubuntu24-Mint22-x86_64.run | Один самораспаковывающийся исполняемый файл |
| ScreenShortsPro-Ubuntu24-Mint22-x86_64.tar.gz | Архив той же готовой папки |
| ScreenShortsPro-Ubuntu24-Mint22-x86_64.txt | Спецификация для страницы скачивания |
| SHA256SUMS.txt | Контрольные суммы файлов выпуска |
| latest-build.json | Указатель на папку последней сборки |

Новая сборка публикуется из staging; предыдущая папка сохраняется.

Для распространения нужен .run либо весь архив .tar.gz; один
`libexec/ScreenShortsPro` не содержит runtime. Спецификацию и SHA-файл положи
рядом со скачиванием. Готовые файлы исключены из исходного Git-репозитория.

.run — статический Go-launcher с вложенным tar.gz: проверяет SHA-256,
безопасно распаковывает в закрытый пользовательский кэш и вызывает обычный
launcher папки. FUSE, установщик, tar и Python для распаковки не нужны.
Из свойств загруженного файла разреши выполнение. Дальнейшие запуски
используют подготовленный кэш с отдельным каталогом для каждого payload.
Это собственный формат .run, не AppImage.

Из каталога, куда скачан или скопирован файл:

~~~bash
chmod +x ScreenShortsPro-Ubuntu24-Mint22-x86_64.run
./ScreenShortsPro-Ubuntu24-Mint22-x86_64.run
~~~

Или распакуй архив .tar.gz целиком файловым менеджером, открой терминал
внутри извлечённой папки и запусти:

~~~bash
./ScreenShortsPro
~~~

Не запускай libexec/ScreenShortsPro напрямую: окружение полного комплекта
настраивает внешний launcher. Права администратора для запуска не нужны.

Для отдельной ручной пробы добавь к команде запуска
`--data-root /абсолютный/путь/к/новой-библиотеке`.
Данные по умолчанию — `$XDG_DATA_HOME/skrinpolka`, иначе `~/.local/share/skrinpolka`;
переустановка/очистка кэша .run не удаляет библиотеку.

## Изоляция, происхождение и приёмка

В portable-профилях появился `linux_runtime_root`. Он выбирает bundled /usr
для bubblewrap; пустое поле оставляет прежнюю лабораторную реализацию.
Общий слот, cgroup-проверка до worker, CPU/RAM/pids/timeout, отключённая сеть,
отмена process tree и отдельный private work сохраняются.
Статический guard позволяет systemd запустить защиту без системного GTK.
При наличии /usr/bin/bwrap используется системная точка входа, чтобы сохранить
профиль AppArmor дистрибутива; иначе берётся комплектный bubblewrap.
Это не отключает проверку лимитов или изоляцию. На системах, запрещающих
user namespaces для переносимых программ, возможности обработки нужно
принимать отдельно; комплект не меняет политики ОС.

WebKit использует комплектные процессы, модули и данные. В его копии
абсолютные имена bwrap/xdg-dbus-proxy заменяются именами из PATH комплекта
с сохранением длины строк; исходные и итоговые SHA/замены записаны в manifest.
Sandbox WebKit не отключается. Лицензии дистрибутивных пакетов, Python wheels,
Go-модулей и модели включены отдельно. GTK/WebKit и другие LGPL-компоненты
остаются динамическими библиотеками, допускающими замену.

`runtime-manifest.json` фиксирует версии, SHA, происхождение и изменения.
`release-manifest.json` — состав, source-id и `manual-pending`.
Побайтовая воспроизводимость разных сборочных машин не обещается.

## Ручная приёмка

Проверки выполняются отдельно от сборки. На текущем срезе они не завершены.

Сценарии: .run из пути с пробелами/кириллицей; перенос полной папки;
отсутствие системных Python/Tesseract/GTK/WebKit; захват/клавиши/трей;
OCR rus/eng и поиск после сохранения; прозрачность/undo/отмена удаления фона;
отказ защиты без bypass, повторный запуск и сохранность библиотеки.
Матрица — отдельные Ubuntu/Mint X11/Wayland, с фиксацией ограничений.
Автоматические проверки/запуски без отдельного запроса не выполняются.
