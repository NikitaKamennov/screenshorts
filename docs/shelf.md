# Библиотека: виды, выбор и действия

Библиотека реализована в общем Go/HTML-коде. На Windows 10 прошла проверка
с искусственной библиотекой; получено подтверждение работы в ручной пробе.
Linux-адаптеры этого среза ещё не проверялись.

## Реализовано

- Миниатюры и таблица, компактная плотность, сохранение вида/порядка в настройках.
- Сортировка всех столбцов данных: имя с естественным порядком чисел, дата,
  содержание, размер PNG, разрешение по площади/ширине/высоте, видимый статус OCR.
- Суточные группы с отступом и разделителем при сортировке по дате; локальные
  календарные дни. В других сортировках разбиение по дням отключается.
- Указательный предпросмотр строки таблицы: PNG, OCR/комментарий и параметры.
  Задержка 220 мс, размещение в пределах окна. Данные экранируются через textContent.
- Чекбоксы, частично выделенное состояние «Все», Shift-диапазон, Ctrl+A,
  Escape, Ctrl+C, Delete. Выбор сохраняется при смене вида/порядка; записи,
  скрытые новым поиском, снимаются с выбора. «Все» включает ещё не показанные.
- Копирование реальных PNG в файловый буфер Windows CF_HDROP; в Linux подготовлен
  text/uri-list через wl-copy/xclip. Копирование OCR/комментариев в текстовый буфер.
- «Поделиться» предлагает файловый буфер (JSON необязателен) и ZIP. Отправку
  выполняет пользователь в своём почтовом клиенте/мессенджере. Облачного API нет.
- ZIP сохраняет исходные PNG и точные JSON-байты с пользовательскими полями,
  версиями и происхождением OCR. Сначала пишется временный архив, итог появляется
  только после успешного закрытия/синхронизации. До 1000 записей/1 GiB на действие.
- Удаление с карточки или строки без открытия, групповое удаление с подтверждением,
  отдельная корзина и групповое восстановление. PNG и JSON копируются и
  синхронизируются перед удалением источника. Совпавшие имена другой версии при
  восстановлении не перезаписываются. Частичные ошибки перечисляются.
- В обоих видах показаны фактические байты PNG и ширина × высота. Размер JSON
  не прибавляется. Папка открывается по адресу внизу библиотеки; ↻/F5 перечитывает
  её после внешнего добавления файлов.

## Группировка содержания

Сравниваются комментарий и актуальный OCR; исправленный OCR имеет приоритет
над исходным. Хэш входных пикселей должен совпадать с текущим PNG. Пустая ручная
коррекция не подменяется исходным текстом. Изображение и visual caption не используются.

Алгоритм: слова Unicode, стоп-слова ru/en, короткая нормализация длинных слов,
TF-IDF и косинусная близость, объединение соседей в группы. Порог 0,34 с двумя
общими словами (или одинаковым единственным словом). На запись берутся до
8192 символов и 96 слов; для кандидатов — 16 редких слов, до 48 соседей на слово,
до 100 сравнений на запись. Это приблизительная лексическая группировка,
не смысловой поиск и не обещание найти все похожие снимки. Синонимы без общих
слов могут не объединиться; цепочки совпадений могут расширять группы.
Расчёт уступает UI каждые 64–128 записей; смена сортировки отменяет старый расчёт.
Текст не записывается обратно в JSON.

## Файлы и ограничения

Корзина находится внутри библиотеки: `.screenshorts-trash/<случайный token>/`.
Это собственная корзина библиотеки, отдельная от системной. Автоочистки и постоянного
удаления из интерфейса пока нет. Она занимает место и не входит в поиск/ZIP
выделенных живых записей. После прерывания операции незавершённые служебные
копии могут остаться на диске; неизвестные файлы автоматически не удаляются.
Восстановление возвращает исходные имена, комментарий и обе версии OCR.
Если удаление застало активный OCR, задача отменяется и восстановленная запись
показывает остановленный статус; повтор можно запустить из карточки.

Идентификаторы и библиотека проверяются в Go, пути из sidecar не принимаются
как назначения. При смене библиотеки старое выделение недействительно.
PNG сверяется по SHA-256; симлинки для файлов/корзины не принимаются.
Экспорт не меняет исходники. Ошибка ZIP не публикует частичный итог.
Копирование PNG отдельно не переносит OCR и комментарии: для полной записи
нужен JSON или ZIP. Импорт ZIP в интерфейсе не добавлялся; распакованную пару
можно положить в библиотеку и обновить библиотеку.

Предпросмотры ограничены 480 пикселями по большей стороне, грузятся по одному
и только возле видимой области/наведения. Кэш — до 32 изображений, DOM —
по 48 записей с «Показать ещё». Полноразмерные снимки для таблицы заранее не читаются.
SQLite/FTS, семантическая модель, переименование и системный Share dialog в этот
срез не входят.

## Проверки

- Go: сценарий PNG+JSON → ZIP → корзина → восстановление с сохранением OCR,
  комментария и digest; конфликт имён без половинной пары; изменённый PNG,
  неверная библиотека/ID/повтор ID; сохранность настроек библиотеки при смене темы.
- Node: сортировка, размеры, диапазон, актуальность/пустая коррекция OCR,
  похожие/непохожие тексты и отмена группировки.
- Реальный Wails/WebView2 на Windows: 72 искусственные записи, два вида,
  заголовки сортировок, группы дней/содержания, Shift/«Все» для скрытых страниц,
  предпросмотр у края окна, одиночное и групповое удаление/восстановление, поиск,
  выбор только результатов, сохранение вида после перезапуска, светлая/тёмная
  тема, выравнивание элементов, клавиши при фокусе на чекбоксе и ↻/F5 после
  внешнего добавления пары PNG+JSON. CF_HDROP проверен чтением трёх
  собственных PNG из файлового буфера Windows. Дополнительный нативный тест
  проверил Unicode-путь и Preferred DropEffect = COPY; переноса вместо
  копирования не запрашивается.
- Архив проверен тестом Go. Отправка в сторонний мессенджер/почтовый клиент,
  диалог ZIP через клавиатуру, Linux, аварийное выключение и очень большая
  библиотека не проверялись.

Чекбокс «Все», счётчик и действия имеют
общий центр и высоту; корзина перенесена в боковую панель.

## Практики, на которые опирается интерфейс

- [GNOME Files: сортировка](https://help.gnome.org/gnome-help/files-sort.html): сортировка списков по столбцам и размеру.
- [Microsoft: форматы файлового буфера](https://learn.microsoft.com/en-us/windows/win32/shell/clipboard),
  [DROPFILES](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/ns-shlobj_core-dropfiles): перенос настоящих файлов через CF_HDROP.

Пользовательские действия описаны в [инструкции](user-guide.md) и встроенной справке.
